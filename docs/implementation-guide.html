Frontend & Backend — Implementation Guide

The concrete “things to do” to build ExamPath: every setup step, the exact folder structure, backend and frontend task lists in build order, with acceptance criteria. Pair this with the Build Bible (the architecture) and the schema.sql (the database).

How the pieces fit: Next.js renders pages & talks to Supabase · Supabase is the database/auth/storage · n8n orchestrates scrape→extract→validate→publish · Workers run Playwright scrapers & the AI extractor. Build them in the order below.
▶
Day one

Quick start

Get the whole stack running locally in under an hour.

# 1. Create the monorepo
mkdir exampath && cd exampath
npm init -y && git init

# 2. Web app (Next.js + TS + Tailwind)
npx create-next-app@latest web --ts --tailwind --app --eslint

# 3. Supabase (local dev stack: Postgres+Auth+Storage in Docker)
npm i -g supabase && supabase init && supabase start
supabase db push        # applies db/schema.sql migration

# 4. n8n (orchestration)
docker run -it -p 5678:5678 -v ~/.n8n:/home/node/.n8n n8nio/n8n

# 5. Scraper worker
mkdir workers && cd workers && npm init -y
npm i playwright crawlee @supabase/supabase-js
npx playwright install chromium
Prereqs: Node 20+, Docker, a Supabase account (or local), and an LLM API key (Claude/OpenAI) for extraction. Keep db/schema.sql from the Build Bible as your first migration.

B1
Backend

Supabase project & schema

  • Create the Supabase projectNote the URL + anon + service-role keys.
  • Apply db/schema.sql as the first migration25 tables, enums, views, RLS, search index — already tested on Postgres 16.
  • Load db/seed.sqlGives you a real SSC CGL 2026 row to build the frontend against immediately.
  • Create a Storage bucket raw-docsHolds scraped HTML/PDF snapshots; set a lifecycle rule to expire old blobs.
  • Verify the read-model viewsv_cycle_next_deadline, v_active_cycles return rows.
Acceptance: select * from v_active_cycles; returns the seeded SSC CGL 2026 with body + exam joined.
B2
Backend

Auth & Row-Level Security

  • Enable Supabase AuthEmail OTP (magic link) + Google OAuth. No passwords.
  • Confirm the profile trigger firesA row auto-creates in profile on signup (handle_new_user).
  • Test RLS boundariesAnon can read published cycles; cannot read draft (null published_at) or another user's user_follow.
  • Wire the eligibility profileDOB, category, qualification saved to profile → feeds personalisation & alerts.
Acceptance: a logged-out request returns only published content; a user can read/write only their own follows & subscriptions.
B3
Backend · §5

Scraper workers

  • Seed the source tableOne row per official page/PDF to watch, with crawl_frequency + parser_hint.
  • Build the fetch worker (Playwright)Render page, handle PDFs, respect robots + rate limits, retry w/ backoff.
  • Change detectionsha256 the normalised content; skip if equal to source.last_hash.
  • Persist snapshotsBlob → Storage; metadata row → raw_document; log a scrape_run.
  • Per-source adaptersStart with SSC (notice list + PDF). Add UPSC, IBPS, RRB, one state PSC.
Acceptance: running the worker on the SSC source with a changed page creates one raw_document and marks scrape_run.changed = true.
B4
Backend · §6–7

AI extraction + validation

  • Extraction serviceLLM w/ structured output → JSON matching the schema; store an extraction row w/ confidence + evidence spans.
  • Entity resolutionFuzzy-match to an existing exam/exam_cycle or propose new — prevents duplicates.
  • Validation scorerRule checks (schema, sanity, links resolve, cross-source) + AI re-read → 0–100 score + report → validation row.
  • The 90% gate≥90 auto; 70–89 human queue; <70 reject. Store the report string for the n8n notification.
  • Eval harness50–100 golden docs w/ known answers; track field accuracy per prompt_version.
Acceptance: feed a known SSC notice → extraction matches the golden answer; a deliberately corrupted date drops the score below 90 and routes to review.
B5
Backend · §9

n8n workflows

Three workflows wire the whole engine together. Build them in n8n, export JSON to automation/n8n/.

WFTriggerDoes
WF-1 ScrapeCron / sourceFetch → hash → if changed → insert raw_document
WF-2 GateNew raw_documentExtract → validate → score → branch (auto / review / reject) + send report
WF-3 PublishApproved versionUpsert content → snapshot version → feed + notify → call /api/revalidate
  • Human-review branchTelegram/Slack with Approve/Edit buttons for the 70–89 zone.
  • Notification fan-outOn publish, match audience & send web push/email §17.
Acceptance: a changed SSC page flows end-to-end and the dashboard reflects it within seconds — no code deploy.
