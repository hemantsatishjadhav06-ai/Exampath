Project Dream · Phase 1 · Information Architecture

Canonical Data Model

The single source of truth for the whole platform. Every scraper, AI agent, Supabase table, Next.js component, SEO tag and notification uses these shapes — if a field isn't defined here, it doesn't exist anywhere. This is the foundation to lock before finalizing the database and the dashboard.

Ships as runnable codeThe exact model is encoded in canonical-model.ts (34 interfaces, 18 vocabularies) — type-checked clean in strict mode. Your Next.js app imports it directly; the Python pipeline mirrors it 1:1; the Supabase tables are its normalized persistence. This document is the readable companion.

The core idea — body → exam → cycle

One modelling decision underpins everything: separate the evergreen exam from its yearly cycle. This is what makes “one universal template, not individual pages” possible and keeps the data non-duplicated.

ConductingBody  (SSC, UPSC, IBPS, RRB, NTA, State PSCs…)        /ssc
   └── Exam  (evergreen brand: "SSC CGL")                    /ssc/cgl
         └── ExamCycle  (a year: "SSC CGL 2027")  ◀── the spine   /exam/ssc-cgl-2027
               ├── ImportantDate · TimelineEvent          (when)
               ├── Eligibility · Vacancy · Fee · Salary   (who / how many / cost / reward)
               ├── SelectionStage · ExamPattern · Syllabus(how you're selected)
               ├── Notification · AdmitCard · Result · AnswerKey · Cutoff · PreviousPaper
               ├── Document · OfficialLink · FAQ · Update (artifacts, links, changes)
               └── SEOMetadata · VersionHistory · AuditLog (SEO + governance)

Every /exam/[slug] page uses the same React components; only the cycle's data changes. Because the exam is evergreen, last year's page keeps its URL, links and SEO authority while a new cycle spins up beside it.

Identity, slugs & URLs

IDs are UUIDs (stable, internal). Slugs are the human, permanent, SEO-facing identity — generated once and never silently changed (a change writes a 301 redirect).

EntitySlug patternURL
ConductingBody{body}/ssc
Exam (evergreen){body}-{exam}/ssc/cgl
ExamCycle{exam}-{year}/exam/ssc-cgl-2027
Update—links to its cycle's url_path
RuleLowercase, hyphenated, ASCII. Year is embedded in the cycle slug so 2026 and 2027 coexist permanently. Canonical URL is stored on the row and echoed in SEOMetadata.canonical.

Assembly · the performance keystone

The Universal Exam Dashboard object

Rule 9 in one artifact. Rather than run 20 queries per visitor, the pipeline pre-assembles one denormalized ExamDashboard object per cycle whenever a validated change lands, stores it (Supabase JSONB + Cloudflare/ISR cache), and every /exam/[slug] visit renders straight from it. Each of your 22 dashboard sections maps to one field → one React component.

The gate

Validation rules

Your validation checklist, made executable. Each extraction is scored; hard failures block regardless of score, and the confidence band decides the route (rule 10).

CheckRuleSeverity
Required fieldstitle, status, and the section's key fields presenthard
Date formatevery date parses as ISO YYYY-MM-DDhard
Date logicapplication_end ≥ application_start; exam ≥ application_end; result ≥ examhard
Age range14 ≤ age_min ≤ age_max ≤ 60soft
Vacancyinteger > 0; category breakdown sums ≈ totalsoft
Feenon-negative; category ∈ vocabularysoft
Duplicate detectionsame cycle+kind+content_hash already present → skipsoft
Difference detectiondiff vs current version; no diff → no update emittedgate
Confidenceweighted score of all checks + model confidencegate
≥ thresholdauto_publish → version + cache rebuild
→
mid bandneeds_review → Telegram + dashboard preview
→
below / hard failrejected → re-queue, alert ops

Example (your rule): exam_end_date < application_start_date → hard fail → rejected. Approved changes always write a VersionHistory row, so any bad publish is one is_current flip from being undone.
